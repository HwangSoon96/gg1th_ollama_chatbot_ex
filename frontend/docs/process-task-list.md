# 실행 규칙 (3-파일 시스템 / 3단계)

대상: `tasks-prd-local-llm-chat.md`
새 세션은 이 파일부터 읽는다.

## 진행 방식
1. 부모 태스크 **하나씩** 처리한다. 여러 개를 한꺼번에 벌리지 않는다.
2. 하위 태스크를 끝낼 때마다 `[x]`로 바꾼다.
3. 부모 태스크 완료 조건 = **검증 통과**. 검증 없이 `[x]` 금지.
4. 작업 중 발견한 문제는 태스크 번호를 새로 붙여 기록한다 (예: `1.8 (추가)`).
5. 완료 후 사용자에게 보고하고 다음 부모 태스크로 넘어간다.

## 검증 (매 부모 태스크마다)
```
cd frontend
npm run lint    # 통과
npm test        # 통과
npm run build   # 통과
```
UI를 건드렸으면 **브라우저로 실물 확인**까지 (라이트/다크/390px).

테스트를 새로 썼으면 **그 테스트가 진짜 버그를 잡는지** 확인한다.
로직을 일부러 뒤집어 실패하는지 본다. 뒤집어도 통과하면 검증 못 하는 테스트다.
(2.8에서 실제로 이 방식으로 헛 테스트를 잡았다.)

## 불변 규칙
- **`backend/` 수정 금지.** `backend/main.py`의 ` M`은 사용자 작업이다. 건드리지 않는다.
- 백엔드 API 계약은 고정: `POST /chat` → `{model, message, elapsed_time}`, `GET /models`.
- 의존성 추가는 이유를 한 줄로 남긴다 (현재 추가분: `vitest` — 에러 분기 5갈래 검증용).
- 커밋 메시지에 AI 흔적 금지.

## 이 환경의 함정
- 패키지 매니저는 **npm** (pnpm 없음).
- gjc `browser` 툴이 WSL2에서 기동 실패 → CDP 직접 제어로 대체.
  `node /tmp/shot.mjs <url> <out.png> <w> <h> <light|dark>`
  (재시작 후 없으면 다시 만들어야 함)
- **백그라운드 프로세스가 bash 호출 사이에 죽는다.**
  dev 서버 기동 + 크롬 기동 + 촬영을 **한 번의 bash 호출 안에서** 해야 한다.
- 크롬은 `--no-sandbox --disable-dev-shm-usage` 필요.

## 현재 지점

실제 백엔드 + Ollama로 왕복까지 확인했다(7.0).

### 디자인 규약 (8.0에서 확정)
- 액센트 호박색은 **의미가 있는 자리에만** — 전송, 생성 중, 활성 모델, 수치.
  장식으로 뿌리면 의미가 죽는다.
- 토큰은 세 개로 나눠 쓴다: `--amber`(글자) `--amber-fill`(면) `--amber-lamp`(장식).
  하나로 둥치면 반드시 어느 한 쪽이 AA를 깨뜨린다.
- **한글에 `text-transform: uppercase`나 넓은 `letter-spacing`을 주지 말 것.**
  한글은 대소문자가 없고 mono 폰트에도 한글 글리프가 없다. 두 번 손해다.
  라턴 계기값(temperature, PYTHON, 모델명)에만 mono를 쓴다.
- 폰트는 self-host. 시스템 폰트 스택은 OS마다 다른 품질로 렌더된다
  (맥=SF Pro, 윈도우=맑은고딕). 같은 화면이 기계마다 다르게 보이면 디자인이 아니다.
- 윈도우 DirectWrite는 가는 획을 먹는다. 본문 `font-weight: 450`으로 두 OS 무게를 맞췄다.
- 대비 계측 스크립트는 **반투명 배경을 합성해야** 한다. 안 하면 멀줦한 곳을 오진한다.
- **한글 제목에 mono를 주지 말 것.** 글자는 sans로 떨어지지만 공백은 mono 폭으로 남아
  어절 사이가 벌어진다. 라턴 데토(LLM, 커서)에만 따로 mono를 준다.
- 한국어 UI 문구는 **단어로 종결**한다. 서술형 부제("~에서 돕니다")는 설명하려는 티가 난다.
- 모델명 뒤에 조사를 붙이지 말 것 — 끝소리를 알 수 없어 "이/가"를 고를 수 없다.
  명사("모델")를 끼워 피한다.
- 애니메이션은 **사용자 행동에 대한 응답에만**. 복원된 데이터가 줄지어 떠오르면
  그건 페이지 로드 연출이다. 첫 렌더의 id를 기억해 가른다.
- 접힌 패널은 `inert`로 포커스를 막는다. `display:none`이 아니므로 전환 애니메이션이
  살아있고, 안 보이는 컨트롤에 Tab이 들어가지도 않는다.
  (계측 주의: `offsetParent`는 `inert`를 반영하지 않는다. 실제로 `.focus()`를 해봐야 한다)
- **스크롤 컨테이너는 높이가 묶여 있어야 생긴다.** `#root`에 `min-height`만 주면
  앱이 무한히 자라고 `html`이 대신 스크롤된다. 안쪽 `overflow-y: auto`는 죽은 채로 남는다.
  증상: `scrollHeight === clientHeight`가 계속 같이 커진다.
- `ResizeObserver`의 관찰 대상을 마운트 시점에 고정하지 말 것. 그때의 `firstElementChild`는
  빈 상태 div라 데이터가 들어오면 떨어진 노드를 보게 된다.
- 로컬 모델은 **깨진 마크다운**을 뿜는다. 표 중간에 코드블록을 끼우면 그 뒤 행은
  표가 아니게 된다. 렌더러만 넣고 끝내면 파이프 문자가 화면에 남는다(`normalizeTables`).
- 브라우저 검사에서 `waitFor(() => $('.composer__send'))` 같은 조건은 위험하다 —
  전송 직전에 이미 참이라 즉시 통과한다. 대기 시작을 먼저 확인하고 끝날 때까지 기다려야 한다.
- **`@media (prefers-reduced-motion)` 블록은 파일 맨 끝에 둔다.** 같은 특이도면
  나중 규칙이 이기므로, 블록 뒤에 `animation:` 선언이 오면 그대로 돌아간다.
  실제로 두 곳이 이렇게 깨져 있었다. 새 애니메이션을 넣으면 **반드시 실측로 확인**할 것:
  가짜 요소를 만들어 `getComputedStyle(el).animationName`이 `none`인지 본다.
- 대화가 길어지면 "사용자가 지금 무엇을 보고 있는가"를 같이 생각해야 한다.
  위로 올려 읽는 중에 도착한 것은 화면 밖에 있어 존재 자체가 안 보인다.

### 이 프로젝트에서 나온 교훈 (다음 세션용)
- 훅 테스트는 파일 상단 `// @vitest-environment jsdom`으로 한다.
  전역 설정을 바꾸면 fetch를 모킹하는 `chatApi.test.js`가 영향받는다.
- `send`는 fire-and-forget이다. 테스트에서는 `await act(async () => ...)`로 감싼다.
- 렌더 중 ref 변경은 lint가 막는다(`react-hooks/refs`). effect로 넣는다.
- **대비는 눈으로 못 본다.** 멀줦해 보이는 회색 메타 텍스트가 3.4:1이었고,
  다크 모드 전송 버튼은 2.89:1이었다. 반드시 계산해서 확인한다.
- **프록시가 오류를 가로채다.** 백엔드가 꺼져 있어도 fetch는 성공하고 502가 온다.
  "서버가 꺼졌다"는 상황을 개발 환경에서 실제로 만들어 봐야 알 수 있다.
- 테스트가 버그를 굳힐 수 있다. 502를 `server`로 기대하던 기존 테스트가 그랬다.
  테스트가 통과한다고 동작이 맞다는 뜻은 아니다.
- 브라우저 시드는 `Page.addScriptToEvaluateOnNewDocument`로 한다.
  navigate 후에 `Runtime.evaluate`로 심으면 이미 마운트된 앱이 빈 배열로 덮어쓴다.
- 조작 스크립트: `/tmp/drive.mjs` (촬영 + 클릭/입력/대기 헬퍼).
  React는 value setter를 가로채므로 `Object.getOwnPropertyDescriptor(proto,'value').set.call(...)`을 써야 한다.
